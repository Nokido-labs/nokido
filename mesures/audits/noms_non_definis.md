# Audit — noms non definis (`app/`, `tools/`)

Brief « session cloud A », 2026-09-29. Branche `claude/audit-noms-non-definis`, creee depuis
`alpha` a `ea3c441`. Environnement cloud Linux, sans hub : git + Python seulement.

## Methode

**La commande du brief ne voit pas ces defauts.** Lancee telle quelle,
`ruff check --select F821,F823,F841,F811 app tools` rend **0 F821** : `ruff.toml` exclut
(`extend-exclude`) precisement les modules herites du monolithe -- `forge_at_dispatch*`,
`forge_handler_*`, `forge_handlers.py`, `forge_hub_handlers*`, `forge_mixin_*`,
`forge_dispatch_*`, `forge_loop.py`, `forge_core_models.py`, `forge_agentic.py`,
`forge_runtime.py`, `forge_ssh.py`, `forge_ui_widgets.py`, `forge_disco.py`, `Nokido.py`,
`**/legacy/**`, `forge_startup.py`... Les trois defauts du brief y sont tous. L'audit a donc
tourne avec `--isolated` (configuration du depot ignoree), `--target-version py314`, en
excluant `_attic/` et `backups/` :

    ruff check --isolated --target-version py314 --select F821,F823,F841,F811 \
      --exclude '**/_attic/**' --exclude '**/backups/**' --output-format concise app tools

-> **531 signalements** : 352 F821, 0 F823, 170 F841, 9 F811, sur 132 fichiers.

**Tri.** Chaque signalement a ete lu dans son code (fonction entiere, appelants par
`git grep`). Constats qui valent pour tout le tableau :

- aucun mecanisme n'injecte de noms dans ces modules : `forge_boot.inject_boot_globals`
  n'ecrit que dans `__main__`, et `get_app_attr` / `_g` LISENT un attribut du monolithe
  sans rien creer dans l'appelant. Un global absent leve donc bien `NameError` ;
- `app.X` et `nokido_agent.app.X` sont **deux objets module distincts** (mesure :
  `app.forge_services is nokido_agent.app.forge_services` -> False, et leurs enums ne
  sont pas egales entre elles) -- base d'un des correctifs (`@services add`) ;
- F841 n'est pas un nom non defini : verdict FAUX POSITIF (« variable inutilisee, sans
  effet ») sauf quand la valeur oubliee revele un vrai defaut -> BUG de logique.

**Correctifs.** Un commit par bug, correctif minimal, sans refactor. Critere : corrige
quand la bonne liaison existe ailleurs sans ambiguite (import, `self` -> `app`,
`_g(...)`, signature du jumeau) ; NON corrige quand il faut une decision (code perdu a
reecrire, changement de comportement, suppression de copie morte) ou quand le defaut
n'est pas un nom (TypeError, logique). Aucun fichier de `CRITICAL_FILES` n'a ete touche.

## Ce qui cassait vraiment (chemins atteignables depuis la TUI)

Tous corriges, chacun avec son commit et son NR :

- **Le SmartRouter n'a jamais route une demande** : `_raw_demande` lue ~100 lignes avant
  son affectation (`forge_dispatch_ai`), UnboundLocalError rattrapee -> repli systematique.
  Juste derriere, `AGENT_BY_KEY` absent aurait transforme toute reponse multi-agents en
  « ❌ Erreur ».
- **Toute reponse LLM contenant un bloc ```bash finissait en « ❌ Erreur »** :
  `extract_commands_from_response` est une METHODE de l'application, appelee comme une
  fonction libre.
- **`@loop` (TUI -> `forge_hub_handlers.handle_loop`) etait inaccessible** : `self` et cinq
  globals du monolithe ; et sa verification de fin (`_post_loop_safe_check`) comme `@apply`
  (`_apply_suggestion`) deleguaient a des noms qui n'existent pas (ImportError).
- **Toute commande distante (`@run`, `@ci`, `@workflow`, reboot)** passait par
  `PrefectManager.run_ssh_command` (`forge_core_models`), qui appelait un `run_ssh` inexistant.
- **`@ids`** levait NameError des sa premiere ligne (`HAS_IDS`), puis sur `self` ; les alertes
  IDS etaient perdues (`escape` absent dans le callback).
- **`@agentic`, `@evolve` (deux copies), `@ragas`, `@services add`, `@ollama status`** : globals
  du monolithe, `self`, et le couple d'enums de deux copies de module. `@ollama status`
  affichait « hors ligne » meme Ollama actif.
- **La confirmation du garde de danger ne pouvait pas s'afficher** (`Vertical` absent de
  `forge_ui_widgets`), ni l'assistant SSH (`Vertical`/`Horizontal` dans `forge_ssh`).
- **Chemins d'erreur muets** : le journal d'erreur de `@loop` (`Path`, `datetime.now()` sur le
  MODULE), six messages d'erreur de `forge_at_dispatch` (`escape`), le resultat de `@run`
  (commande DEJA executee quand l'affichage levait).
- **Masquage** : `forge_handlers` redefinissait `_handle_rag` en stub synchrone qui ecrasait le
  vrai handler async (`# noqa: F811` : ruff ne le signalait plus) ; et le wrapper
  `classify_with_cmd` importait un `_compose_main` inexistant -> ImportError a chaque appel,
  alors que le canari de demarrage (qui ne verifie que la PRESENCE des noms) passait.

  s'importent a l'identique sur `alpha` et sur la branche (aucun cycle introduit), et chaque
  cible d'import local ajoute existe (`forge_app_context`, `forge_prefect`, `forge_loop`...).

  branche dans le cloud, faute de `rich`/`textual`/`aiohttp` -- environnement, pas regression.
- **Limites** : jouees sous **Python 3.14.0rc2 (Linux)**, pas sous Windows. Plusieurs modules
  (dont `forge_code.py`, `Nokido.py`) utilisent la syntaxe f-string de 3.12+ : sous Python 3.11
