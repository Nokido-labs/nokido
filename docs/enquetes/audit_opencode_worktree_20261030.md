# Audit OpenCode Worktree & Instance Config (2026-10-30)

Audit de conformité du lanceur OpenCode (`_delegate_to_opencode`) et de sa configuration d'instance (`_config_opencode_instance`) vis-à-vis du travail dans le worktree de tâche dédié.

| Constat | ligne | consequence | correctif propose |
| :--- | :--- | :--- | :--- |
| **ACPClient lancé avec `cwd=wt` mais sans initialisation projet neuf explicite** : `wt = str(_workdir_opencode(inst))` résout `_WT_TACHE.get()` si défini, et est passé à `ACPClient(agent="opencode", cwd=wt, env=env)`. Cependant, contrairement à agy (`--new-project`), ni `initialize()` ni `session_new()` ne transmettent de paramètre de projet ou racine de workspace. | 4389, 4464, 4471 | OpenCode démarre dans `wt`, mais en l'absence de directive projet explicite dans le protocole ACP (`session_new`), l'agent peut ne pas réinitialiser complètement le contexte projet ou l'index de workspace. | `sid = client.session_new() # ou passer workspace_root si supporté par ACPClient` |
| **La configuration d'instance ne pointe PAS vers un worktree habituel** : `_config_opencode_instance` ne définit aucune clé de chemin ou de workspace (`$schema`, `mcp`, `permission`, `model`, `provider`), donc ne pointe vers aucun worktree habituel en dur. | 4184-4224 | L'instance n'est pas polluée par un worktree historique dans sa config JSON ; son arborescence repose uniquement sur le répertoire courant (`cwd=wt`). | `# Aucun correctif : _config_opencode_instance est neutre vis-a-vis des chemins de worktree` |
| **Vérification de capacité liée au worktree habituel** : `_peut_lancer_opencode` vérifie l'existence de `_workdir_opencode(nom) / ".git"`, qui hors contexte de tâche pointe vers le worktree habituel (`nokido_worktrees/<nom>`). | 3990-3992 | Si le worktree habituel de l'instance n'existe pas, la tâche est rejetée en amont même si un worktree de tâche dédié pourrait être créé. | `wt = Path(_WT_TACHE.get()) if _WT_TACHE.get() else _workdir_opencode(nom)` |
