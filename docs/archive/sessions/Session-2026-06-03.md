# Session 2026-06-03 — additions

Changelog (companion to [Session-2026-05-31](Session-2026-05-31.md)).

## Veille pipeline — ChainExecutor en daemon

- **Problem** : `app/forge_chain_executor.py::start_loop()` n'était lancé par aucun
  daemon → les chains de veille restaient `pending` (diagnostiqué via `/debug/stacks` :
  seuls `provider_watcher` + `IdleWatchdog` tournaient).
- **Fix** : `NokidoChainExecutor` ajouté comme service supervisor **wave 4**
  (`services.toml`) → `start_loop()` poll 5 s. Activé à chaud via `/supervisor/reload`
  (sans restart). + `supervisor.ts /supervisor/service/start` : fallback sur `SERVICES`
  et création de state à la volée pour réveiller un service `disabled` (fin du 404
  wake-on-demand).

## Embed cascade — local-first + skip unconfigured

- **Problem** : `forge_embed_router.PROVIDERS` était **cloud-first**
  (`modal, voyage, jina, brain_worker, hf`) → embeddings **NULL** dans les contextes
  sans egress (ChainExecutor, trusted) ; les providers non configurés (modal) claquaient
  le circuit breaker pour rien. Corpus non cherchable.
- **Fix** : ré-ordonné **local-first** (`brain_worker` en tête) + `_provider_has_creds()`
  skip les providers sans clé/URL avant appel (tue le breaker `modal not_configured`).
- **Verdict embedder local** : `NokidoEmbedWorkerIsolated` (BGE-M3 ONNX CPU :5557) fait
  `bad allocation` (OOM sur Cast node) à cap 3/5/6 GB — **pas** un problème de cap. Worker
  laissé OFF ; chantier réparation (ré-export ONNX / int8) en attente.

## Incident — hub crash (egress synchrone) + RAM

- Un fetch egress **5-URL synchrone** via `run` (jusqu'à 300 s) a bloqué un worker hub →
  crash, aggravé par la pression RAM (Docker + embed worker, 81 %). Recovery : **couper
  Docker** a libéré la RAM → le supervisor a pu relancer le hub (cohérent avec l'historique
  OOM hub). **Leçon** : fetch lourd/multi-URL → `run_job` détaché, jamais synchrone via hub.
