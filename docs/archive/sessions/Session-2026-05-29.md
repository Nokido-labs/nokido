## 1. Pipeline veille débloquée — keeper SearXNG

Deux causes empilées dans `tools/forge_searxng_keeper.py` :

1. **État container mal testé.** `docker inspect` renvoie `.State.Status = "exited"`
   (jamais `"stopped"`) → l'ancien `if state == "stopped"` ne matchait rien et
   tombait dans `docker run --name` → **Conflict: name already in use**.
2. **Aucun `settings.yml` monté.** Run nu → SearXNG défaut `limiter: on` + JSON
   désactivé → `format=json` renvoie **403** → veille KO même container « up ».

**Fix :** tout état ≠ running/absent → `docker start`, fallback `rm -f` + run frais ;
génération de `sandbox/searxng/settings.yml` (`formats:[html,json]`, `limiter:false`,
`secret_key` persisté) monté via `-v`, fichier garanti **avant** le run (sinon docker
auto-crée un dossier → bind dir↔fichier échoue). Recreate si running mais sonde json KO.
Validé : `/search?format=json` → **200**. Voir [SearXNG Keeper](../../wiki/SearXNG-Keeper.md).

Commits : `7d57075d`, `528d922a`.

## 2. Contrôle superviseur authentifié

`tools/forge_supervisor_ctl.py` était antérieur au gate auth Phase 23A → `401` sur
`POST /supervisor/*`. Ajout de la résolution token (`LAFORGE_SUPERVISOR_TOKEN` sinon
`FORGE_MCP_TOKEN`, env puis vault DPAPI machine-wide) + header `Authorization` brut.

→ Un client ring 2 peut désormais restart un service via
`run action=trusted_script path=tools/forge_supervisor_ctl.py script_args="restart <svc>"`
(compte LaForgeTrusted, voie privilégiée légitime). Commit `88f55116`.

## 3. Proprioception whoami — cross-ref santé

`hub whoami` était aveugle à une infra cassée tant qu'aucun job/chain n'était en file
(RCA : SearXNG down + chains veille expirées → faux « rien à reprendre »). Ajout d'un
cross-ref `GET :8765/supervisor/status` : champ **`services_degraded`** + `next_actions`
de restart pour les services ayant essayé+échoué (`restarts>0`) ou en état dur.
Helpers purs `whoami_degraded_services` / `whoami_health_actions`. Commit `0a7a85e2`.

## 4. Gateway OpenAI souverain firewallé (Golden Rule #4)

`tools/forge_openai_proxy.py` (`:7777/v1`) envoyait au LLM **sans firewall**. Ajout de
`pre_flight` (ring 3 : DLP redact → `safe_task` upstream, injection/ring → **403**) +
`post_flight` (SSRF/leak/hallucination → **502**) + `restore` (placeholders DLP
retraduits), sur non-stream **et** pseudo-stream. Validé : injection → **403** avant
tout appel LLM. Voir [OpenAI Gateway](../../wiki/OpenAI-Gateway.md). Commit `83af3b16` + doc `3f4ce76f`.
