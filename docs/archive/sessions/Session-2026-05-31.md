# Session 2026-05-31 — additions

Changelog of recent additions (companion to [Session-2026-05-29](Session-2026-05-29.md)).

## RAG corpus tiering — anti-repollution guard
- **Problem found** : the vectorized tier had drifted back to ~55 % pollution
  (150 k embedded, ~83 k external libs) — 10+ embed scripts `UPDATE embedding` on
  `embedding IS NULL` **without** the `forge_tier_policy.HOT_TIER_SQL` filter.
- **Fix** : `tools/forge_tier_guard_install.py` installs a DB trigger
  (`forge_tier_guard`, BEFORE UPDATE OF embedding → `RAISE(IGNORE)` on cold-origin)
  — a single chokepoint catching all present **and future** embed paths. Self-test
  block-cold / allow-hot. Plus `forge_retier_corpus.py` re-applied : 150 380 → 22 568
  embedded (cold rows kept FTS-searchable).
- **Audit** : `tools/forge_embed_corpus_audit.py` measures the vectorized tier
  composition any time. After fix : pollution 83 268 → 3.

## License governance — AGPLv3 guard
- `tools/forge_license_guard.py` : scans installed-dependency licenses (stdlib
  `importlib.metadata`, reads SPDX `License-Expression`). **Blocks** SSPL / BSL / BUSL /
  Elastic / proprietary / CC-NC / GPLv2-only. Wired into **pre-commit** (on
  `requirements*`/`pyproject` change) + **CI** (`license-scan` job). Tested : 187 ok,
  0 incompatible.
- Confirms the existing **CLA + dual-licensing** stack (`docs/CLA.md`, `cla.yml`,
  `COMMERCIAL.md`) is complete.

## SFT — local scaling recipe
- `tools/forge_sft_{export,train,eval}.py` refined after a multi-LLM consultation :
  LR 2e-4 → **2e-5**, conservative LoRA (`q/v`, r16/α32), **early-stopping** on
  eval-loss, `--bf16` / `--completion-only` flags, base → **Qwen2.5-Coder-3B**,
  MBPP harvested (~1 k examples). Diagnosis : the prior 0 % held-out was the *recipe*
  (LR + data), not the hardware.
